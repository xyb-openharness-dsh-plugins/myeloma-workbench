### 定义

多发性骨髓瘤（multiple myeloma，MM）是克隆性浆细胞在骨髓内增殖的血液系统肿瘤，属浆细胞疾病谱。同一谱系里还有两种前驱状态：意义未明的单克隆丙种球蛋白病（MGUS）与冒烟型（无症状）骨髓瘤。三者按「有没有靶器官损害」这条线区分；本台只记录医生写下的诊断原文，不替人判断处在哪一档。

常见表现的框架是 **CRAB**：血钙升高（C）、肾功能不全（R）、贫血（A）、骨病变（B）。文献里的诊断框架还把骨髓中克隆性浆细胞比例、受累/未受累游离轻链比值、影像学发现等指标并进来（常合称 SLiM 指标）。`docs/BRIEF.md` 记录本台覆盖确诊（CRAB/骨髓）、诱导治疗、自体移植、维持、复发再治疗与支持治疗（骨保护 / 感染 / 肾）全程。

两个层次要分开，这是本项目最容易写错的地方：

- **分期**：ISS 用 β2-微球蛋白与白蛋白两个变量分三期；R-ISS 在 ISS 的基础上加入 LDH 与细胞遗传学信息。
- **危险度 / 细胞遗传学**：del(17p)、t(4;14)、t(14;16) 这类异常本身是另一层信息，在 R-ISS 里是**输入变量之一**，不是与分期并列的「第三套评分」。本台把「分期」与「细胞遗传学结果」分成两个字段存，不互相推导，也不据此写「预后怎样」。

按分泌的免疫球蛋白重链，常见类型有 IgG 型、IgA 型、轻链型等。轻链型只分泌游离轻链，血清蛋白电泳上可能看不到 M 峰——这就是本台把游离轻链（FLC）单独做趋势的原因。

### 目前治疗全景概要

按治疗阶段与线序分组，只列类别，不含剂量、疗程与选择条件。

- **诱导治疗（初治）**：蛋白酶体抑制剂、免疫调节剂、抗 CD38 单抗这三类药物的联合方案，以及传统化疗，被列为诱导阶段的类别；是否走移植路线由医生按年龄、体能和合并情况判断。
- **自体造血干细胞移植**：适合移植者的一个治疗环节。本台只记里程碑日期（采集、回输、植入），不评价移植效果。
- **维持治疗**：诱导或移植之后的长期给药类别。
- **复发 / 难治**：换用未使用过的药物类别、参加临床研究、细胞治疗与双特异性抗体类被列为可选类别之一（国内获批状态与可及性需单独核实）。
- **支持治疗**：骨保护（双膦酸盐 / 地舒单抗类别）、感染预防与疫苗、肾功能相关处理、贫血与血钙的处理类别。
- **贯穿全程**：M 蛋白、游离轻链、血钙 / 肌酐 / 血红蛋白的复查节奏由医生安排；本台只记数值、日期与单位，不判定「是否进展」。

以上是文献与指南里列出的手段，按病期与线序排列，**不代表任何一项适合你**。选哪一个，这一句需要问你的医生。

## 开发与本地验收

需要 Node.js 22+、Git、包管理器和可用 DSH Desktop；采用 SQLite 时另核验 node:sqlite 版本条件。宿主 peers 的范围仅是模板基线，请与目标 Desktop 实际依赖核对。

```bash
npm install
npm run check
npm run pack:check
npm pack
```

`npm run check` 只保证"能装"（语法 + 装包合同），第一天就该是绿的。`npm run audit` 管"还是不是家族里的一员"：版本三处一致、`lib/layout.js` 面板参数单一来源、检查链完整、文档与密钥卫生，**只看代码与文件，不看文档自述**。新项目刚生成时 audit 必然有 fail，那是待办清单；交付/发布前必须清零，存在 fail 不得发布（`npm run release:check` 一次跑完两者）。

跑的时间点：**每次改完**跑 `check`；**G2 原型确认后、写业务代码前**先跑一次 `audit`（这时缺的多是 `lib/layout.js`、`VERSION` 这类结构，越早补越便宜）；**交付/装机前**必须跑 `release:check`；**发布或投稿前**把 `npm run audit --json` 的 `xx/xx 通过 · N 失败 · M 待人工` 抄进 `docs/RELEASE.md` 的「家族一致性」一行。`✗` 是结构缺口（补齐，或在 `docs/DEV-REQUIREMENTS-<日期>.md` 写明偏离理由并由用户确认），`!` 是需人工判断的项（逐条给「已人工确认 / 确实没有」）。

`npm install` 可能按 npm 策略解析 peer；勿为消警告重复打包宿主 runtime。客户端本身是单文件；引入 TS/组件库后需添加构建步骤并保留单文件导出。

本地安装入口以当前 Desktop/CLI 帮助为准。安装后按 [docs/06-VALIDATION-AND-RELEASE.md](docs/06-VALIDATION-AND-RELEASE.md) 与官方自测完成真实 UI 验收，并填写 [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md)。静态检查不代表已加载。

Logo 来源与使用限制见 assets/README.md。许可证、作者、仓库/发布策略由本项目维护者确认后填写；模板默认为 private/UNLICENSED。
