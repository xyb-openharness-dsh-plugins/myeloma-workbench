### 定义

多发性骨髓瘤（multiple myeloma，MM）是以克隆性浆细胞增殖为特征的浆细胞肿瘤。浆细胞主要位于骨髓，异常克隆可产生单克隆免疫球蛋白或其片段（M 蛋白），疾病也可能出现溶骨性病灶。疾病分类需与意义未明的单克隆丙种球蛋白病（MGUS）、冒烟型骨髓瘤（SMM）及浆细胞瘤等区分；诊断依据完整检查和临床团队记录，本台不自行判断。

CRAB 框架涵盖高钙血症、肾功能损害、贫血和骨病变；SLiM 还涉及骨髓克隆性浆细胞比例、游离轻链比值和 MRI 病灶等定义事件。按分泌类型可见 IgG、IgA 等重链型及轻链型；轻链型记录可能需单独查看血清游离轻链（FLC），不能只凭单一检测推断病情。

ISS / R-ISS 是分期框架；细胞遗传学结果与分期相关，但不是可互换字段。del(17p)、t(4;14) 等结果不由本台自动换算为个人风险结论。美国 SEER 2019–2023 数据报告诊断中位年龄为 69 岁，仅是美国人群统计，不代表其他地区分布或个人情况。

### 医学资料规范和指南情况

本台把指南、共识、分类和患者信息分别登记。NCCN 患者版 PDF 和专业指南目录有官方入口，但 PDF 正文未读取，专业正文可能需要登录；目录索引可见 Multiple Myeloma Version 2.2027，本项目未取得或核验该版正文。IMWG 诊断标准可访问 IMF 托管摘要，并提供 2014 年原始论文 DOI；摘要和 DOI 入口不等于当前版本全文已审阅。CSCO 可访问指南汇编获取信息和更新解读回放，均不是本项目所列指南全文。WHO/IARC 在线分类可见分类层级；第五版 Volume 11 出版信息为 2024 年，完整内容需通过图书或订阅访问。NCI PDQ（2025-04-25 更新）为美国语境二次资料。

未取得原件的资料只登记入口、版本状态和用途，不引用未核对的条文、推荐等级或剂量。入口可访问不等于内容已经审阅。具体机构链接、状态与访问限制见 [疾病概要来源表](docs/DISEASE-PRIMER.md#0-原件与链接状态本项目的前提)。

### 目前治疗全景概要

以下按病程阶段列举治疗类别，帮助识别术语；不比较方案，不给出治疗顺序或个人适用性判断。

- **初治阶段 · 诱导治疗**：可能涉及蛋白酶体抑制剂、免疫调节剂、抗 CD38 单抗及糖皮质激素等药物类别，组合依指南版本和临床背景而异。
- **部分患者的治疗环节 · 自体造血干细胞移植**：涉及干细胞动员、采集、预处理、回输及恢复随访等环节；本台只记录日期和原始资料，不评估是否适合移植。
- **治疗后阶段 · 巩固与维持**：列出巩固和维持治疗类别；方案及持续时间以医生记录和当前指南原文为准。
- **复发或难治阶段 · 后线治疗与研究**：涉及不同药物类别、细胞治疗及临床研究等信息；批准状态、适应症和地区可及性需另查现行官方资料。
- **全程支持**：骨骼健康、感染预防和疫苗记录、肾功能与贫血等支持管理类别；本台不生成个体处置建议。
- **贯穿全程 · 复查与病程记录**：M 蛋白、游离轻链、血常规、血钙、肌酐和影像等检查依临床安排。记录页保留日期、单位、来源与方法，不自动判断进展。

以上是文献与指南里列出的手段，按病期与线序排列，**不代表任何一项适合你**。选哪一个，这一句需要问你的医生。

## 开发与本地验收

需要 Node.js 22+、Git、包管理器和可用 DSH Desktop；采用 SQLite 时另核验 node:sqlite 版本条件。宿主 peers 的范围仅是模板基线，请与目标 Desktop 实际依赖核对。

```bash
npm install
npm run check
npm run pack:check
npm pack
```

`npm run check` 只保证"能装"（语法 + 装包合同），第一天就该是绿的。`npm run audit` 管"还是不是家族里的一员"：版本三处一致、`lib/layout.js` 面板参数单一来源、检查链完整、文档与密钥卫生，**只看代码与文件，不看文档自述**。新项目刚生成时 audit 必然有 fail，那是待办清单；交付/发布前必须清零，存在 fail 不得发布（`npm run release:check` 一次跑完两者）。

跑的时间点：**每次改完**跑 `check`；**G2 原型确认后、写业务代码前**先跑一次 `audit`（这时缺的多是 `lib/layout.js`、`VERSION` 这类结构，越早补越便宜）；**交付/装机前**必须跑 `release:check`；**发布或投稿前**把 `npm run audit --json` 的 `xx/xx 通过 · N 失败 · M 待人工` 抄进 `docs/RELEASE.md` 的「家族一致性」一行。`✗` 是结构缺口（补齐，或在 `docs/DEV-REQUIREMENTS-<日期>.md` 写明偏离理由并由用户确认），`!` 是需人工判断的项（逐条给「已人工确认 / 确实没有」）。

`npm install` 可能按 npm 策略解析 peer；勿为消警告重复打包宿主 runtime。客户端本身是单文件；引入 TS/组件库后需添加构建步骤并保留单文件导出。

本地安装入口以当前 Desktop/CLI 帮助为准。安装后按 [docs/06-VALIDATION-AND-RELEASE.md](docs/06-VALIDATION-AND-RELEASE.md) 与官方自测完成真实 UI 验收，并填写 [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md)。静态检查不代表已加载。

Logo 来源与使用限制见 assets/README.md。许可证、作者、仓库/发布策略由本项目维护者确认后填写；模板默认为 private/UNLICENSED。
